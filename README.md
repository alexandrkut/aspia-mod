Aspia
=====

Remote desktop, file transfer and system information tool.

Этот форк
---------

Телеграм-канал: https://t.me/aspia_mod

Мод поверх оригинала Aspia 3.3.5 для своего парка машин: подключение из командной
строки, отключение 2FA по ролям, удалённое управление хостами через роутер, экспорт
установщиков и свой сервер обновлений. Ниже — всё, что меняет мод.

Актуальная версия — [v3.3.5.2](https://github.com/alexandrkut/aspia-mod/releases/tag/v3.3.5.2).

Установка
---------

Пакеты — в [релизах](https://github.com/alexandrkut/aspia-mod/releases):

- `aspia-client-<версия>-mod-x86_64.msi` — клиент для Windows;
- `aspia-host-<версия>-mod-x86_64.msi` — хост для Windows;
- `aspia-router-<версия>-mod-x86_64.msi` — роутер для Windows;
- `aspia-router-<версия>-mod-x86_64.deb` — роутер для Linux (Debian 10 и новее).

Тихая установка:

    msiexec /i aspia-client-3.3.5.2-mod-x86_64.msi /qn
    sudo dpkg -i aspia-router-3.3.5.2-mod-x86_64.deb

Повторный запуск уже установленного пакета переустанавливает его. Автоматическое
обновление включено по умолчанию (см. раздел «Обновление» ниже).

Изменения мода
--------------

**Клиент**

- **Подключение через командную строку.**  
  Ключ `--connect` (он же `-c`) принимает ID записи адресной книги, ID хоста или адрес
  хоста. Логин и пароль для этой сессии задаются ключами `--username` и `--password`,
  вид сессии — ключом `--session-type` (`desktop`, `file`, `info`, `chat`, `terminal`).
  Хост, названный по адресу, подключается напрямую, без роутера. Запрос от второй копии
  клиента передаётся уже запущенной, а не открывает второе окно.

- **Переподключение при обрыве.**  
  На экране разорванного соединения — кнопка «Переподключиться». Подключение
  ограничено 20 секундами: не успело — через 10 секунд начинается автоматическая
  повторная попытка, и так по кругу; на экране виден отсчёт (до конца попытки и
  до повтора). Автоповтор срабатывает и при внезапном обрыве уже установленного
  соединения — закрывать вкладку, чтобы переподключиться, больше не нужно.

- **Режим просмотра.** *(только для пользователей роутера с ролью ADMIN)*
  Пункт «Подключиться для просмотра...» в правом клике по хосту — в списке хостов
  роутера и в пространствах. Сессия просмотра ничего не отправляет на хост: мышь,
  клавиши, текст и буфер обмена блокируются и клиентом, и хостом; в панели
  инструментов — отметка «View only». Сам хост при просмотре не меняется: обои,
  эффекты и разрешение экрана остаются как были; курсор хоста виден, а курсор
  клиента — системный знак «действие недоступно». Вкладка и окно просмотра
  помечены отдельной иконкой.

- **Уведомления о подключении по хостам.** *(только для пользователей роутера с ролью ADMIN)*
  В диалоге «Изменить хост» — три галки: «Уведомлять о просмотре» (по умолчанию
  выключено), «Уведомлять об управлении» и «Уведомлять о файлах» (по умолчанию
  включены). Выбор хранится по хосту на клиенте и переживает его перезапуск.
  Подавить уведомление может только администратор через роутер: сессия
  менеджера, оператора и прямое подключение всегда уведомляют хост.

**Хост**

- **Экспорт инсталлера хоста с перезаписью настроек.**  
  При экспорте можно включить «Затирать старые данные при установке». Тогда настройки
  хоста (адрес роутера, пользователи, параметры доступа) перезаписываются данными из
  инсталлера и поверх уже стоящего хоста; без галочки они переносятся только при первой
  установке.

- **Экспорт Quick Support с пользователями хоста.**  
  Галочка «Выгружать пользователей этого хоста» кладёт в пакет пользователей: на такой
  хост можно войти своим логином и паролем, а не только по одноразовому. Пароли в пакет
  не попадают — только соль и проверочное значение.

- **Иконка хоста на рабочем столе не создаётся.**
  Галочка «Создать на рабочем столе» в инсталлере хоста не отмечена по умолчанию; ярлык
  в меню «Пуск» остаётся.

- **Окно уведомления показывает только видимые сессии.**
  Всплывающее окно с подключёнными сессиями появляется, только если есть сессии
  с включённым уведомлением; сессии с отключённым уведомлением в списке не
  показываются. Когда видимых сессий не остаётся, окно закрывается — раньше оно
  могло остаться висеть после отключения. Сессия просмотра в списке — с иконкой
  просмотра.

- **Режим экрана восстанавливается только если сессия его меняла.**
  При отключении сессии хост возвращает режим экрана, только когда сам его менял.
  Раньше режим сбрасывался к настройкам по умолчанию при каждом отключении — если
  они не совпадали с текущими, экран переключался на мгновение.

**Роутер**

- **Отключение 2FA для каждого типа доступа.**  
  В конфиге роутера 2FA выключается отдельно для администратора, менеджера и оператора:

      [router]
      two_factor_admin=0
      two_factor_manager=0
      two_factor_operator=0

  Роль с выключенным переключателем входит без кода, и каждый такой вход пишется в лог
  роутера. По умолчанию 2FA включена для всех трёх ролей.

- **Удалённое управление хостом через роутер.** *(только для пользователей роутера с ролью ADMIN)*  
  Пользователи, настройки обновлений, полный конфиг из файла, массовые операции с этими
  функциями (с отчётом по выполнению).
  Массовые операции не ждут оффлайн-хосты: хост, не подключённый к роутеру, исключается
  из прогона заранее — в превью он строкой «пропущен», без запросов и без ожидания
  таймаута.

- **Четвёртый блок версии в списке хостов.**  
  Хост кладёт полную строку версии (`3.3.5.1-mod`) в телеметрию, роутер показывает её в
  колонке «Версия». Сравнения версий и рукопожатие не тронуты.

- **Роутер для Debian 10.**  
  Собирается без частей, которые рисуют: без Qt Gui и виджетов, без кодеков и X11.
  Требует только `libdbus-1-3` и glibc 2.28; C++ runtime вкомпилирован статически.

**Обновления и пакеты**

- **Обновления идут через свой сервер.**  
  Проверка обновления включена по умолчанию: клиент и хост обращаются к серверу
  мода — адрес и ключ подписи вшиты в сборки (с 3.2.2.3), поэтому обновления внутри
  линии 3.3.5 идут пакетами мода, а не оригинала. Адрес и ключ можно переопределить
  в настройках. После применения обновления клиент запускается заново сам.

- **Инсталлеры ставятся поверх любой версии.**  
  Пакет удаляет ранее установленную копию с тем же кодом обновления — и оригинальную, и
  мод другой линии версий, — поэтому в списке установленных программ остаётся одна
  запись. Повторный запуск уже установленного пакета переустанавливает его, а не
  предлагает «Изменить, восстановить или удалить». В названии продукта видна отметка
  `(mod)`, версия остаётся числом.

**Чего в этой линии нет:** поддержки хостов версии 2.7 — она осталась в линии 3.1
(клиент `3.1.2.13-mod`, роутер и relay линейки 3.0). Хосты 2.7 подключаются только
клиентом 3.1.2.13-mod через `Aspia Router 3.0.37.2-mod` и relay линейки 3.0.

**Несколько мониторов одновременно** — в 3.3.5 это штатное средство программы (экран
всего рабочего стола), отдельной правки мода для него больше нет.

Где это в интерфейсе:

- Подключение из командной строки — ключ `--connect` с ID записи адресной книги, с ID
  хоста или с его адресом; логин с паролем — `--username` и `--password`, вид сессии —
  `--session-type`.
- Управление хостом через роутер — правый клик по хосту во вкладке «Управление»:
  «Настройка обновлений хоста...», «Пользователи хоста...», «Полный конфиг хоста (из
  файла)...». При выборе нескольких хостов — те же операции разом («Добавить юзера на
  хосты...» и так далее) с превью, матрицей результатов и отменой.
- Экспорт — кнопка «Экспорт» в окне настроек хоста: «Установщик» (с галочкой
  «Затирать старые данные при установке») и «Быстрая поддержка» (с галочкой
  «Выгружать пользователей этого хоста»).
- Переподключение — кнопка «Переподключиться» на экране обрыва соединения; отсчёт
  на этом экране показывает, сколько осталось до конца попытки подключения
  (20 секунд) и до автоматического повтора (10 секунд).
- Отключение 2FA по ролям — конфиг роутера, секция `[router]`, ключи
  `two_factor_admin`, `two_factor_manager`, `two_factor_operator`.
- Режим просмотра — правый клик по хосту «Подключиться для просмотра...» (список
  хостов роутера и пространства, только для ADMIN); отметка «View only» — в панели
  инструментов сессии.
- Уведомления о подключении — правый клик по хосту «Изменить хост»: галки
  «Уведомлять о просмотре», «Уведомлять об управлении», «Уведомлять о файлах»
  (видны администратору).

Обновление
----------

Проверка обновлений включена по умолчанию: клиент и хост обращаются
к серверу мода (адрес и ключ подписи вшиты в сборки с 3.2.2.3): машины внутри
линии 3.3.5 получают обновления автоматически, машины линии 3.2.2 —
предложение обновиться до 3.3.5.2. В сборке 3.2.2.2 вшитый адрес
задан без пути `/updates` — для неё адрес устанавливают вручную в настройках.
После применения обновления клиент запускается заново сам.
